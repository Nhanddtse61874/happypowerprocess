      Create `skills/sync-stack-skill/SKILL.md` — driver for `/sync-stack-skill <stack>` (or `--all`).

      ### Frontmatter
      ```yaml
      ---
      name: sync-stack-skill
      description: Three-way merge a project stack snapshot with the latest plugin default. Use when user types /sync-stack-skill <stack> or wants to pull plugin updates into customized snapshot.
      ---
      ```

      ### Section a — Plugin Path Detection
      Re-use plugin path detection block from `skills/init-project/SKILL.md` section a.

      ### Section b — Argument Parsing
      - `/sync-stack-skill <stack>` → sync single stack.
      - `/sync-stack-skill --all` → loop over every registry entry where `source != "project"`.
      - No argument → prompt `❓ Stack name? (or 'all' to sync all):`.

      ### Section c — Pre-sync Checks
      Read `.claude/stack-skills/registry.json`. For target `<name>`:
      - If entry not found → abort: `Stack '<name>' not in registry. Use /add-tech-stack <name> to register first.`
      - If `entry.source == "project"` → abort: `'<name>' is project-only (no plugin source). Sync not applicable. Use /add-tech-stack <name> to edit.`
      - If `entry.source == "plugin"` AND no `.claude/stack-skills/<name>/SKILL.md` exists → output: `'<name>' is using plugin default unchanged. Nothing to sync.` Exit gracefully.
      - If snapshot file missing but `source == "customized"` → warn + auto-fallback: reset registry source to `plugin`. Exit.

      ### Section d — Common Ancestor Resolution
      For 3-way diff: ancestor = plugin version that the snapshot was originally synced from. Use `entry.synced_from_plugin_version` to identify the historical plugin file.

      Strategy for v5.5.0 (no plugin git history available at runtime):
      - **Trust ancestor = current plugin file** if `synced_from_plugin_version` matches plugin's current version (no plugin updates since last sync → nothing to merge, exit).
      - If versions differ but ancestor file unavailable → fallback strategy: treat plugin's CURRENT content as ancestor (degraded 2-way diff between snapshot and plugin). Warn: `⚠ Cannot retrieve historical plugin v{X} content. Falling back to 2-way diff (snapshot vs plugin v{Y}). Conflict patterns may be approximate.`

      Future improvement (v5.6.0+): plugin ships archive of section content per version under `docs/claude/history/<version>/`. Out of scope for v5.5.0.

      ### Section e — Section-by-Section Diff
      Parse target SKILL.md (snapshot at `.claude/stack-skills/<name>/SKILL.md`) and plugin default (at `{PLUGIN_PATH}/skills/implementer-<name>/SKILL.md`) into sections by markdown `## ` heading. For each section, classify per spec §8.4:

      | Pattern | Detection | Default action |
      |---|---|---|
      | Both unchanged | ancestor == plugin == snapshot | skip silently |
      | Plugin updated, user unchanged | ancestor == snapshot, plugin != ancestor | take-plugin (no prompt) |
      | User updated, plugin unchanged | ancestor == plugin, snapshot != ancestor | keep-mine (no prompt) |
      | Both updated | ancestor != plugin AND ancestor != snapshot | per-section prompt |

      For "Both updated" sections: prompt `❓ Section ## <name>: [keep-mine / take-plugin / manual-merge / show-detailed-diff]`.

      ### Section f — Manual Merge Sub-flow
      When user picks `manual-merge`:
      - Display 3-pane view in transcript:
        ```
        ── ANCESTOR (plugin v{X}) ──
        [content]
        ── PLUGIN (v{Y}) ──
        [content]
        ── YOUR SNAPSHOT ──
        [content]
        ```
      - Prompt `❓ Paste your manually-merged content (multi-line, end with empty line):`
      - Prompt `❓ Confirm save merged content? [y/edit/cancel]`.

      ### Section g — Apply-All-Remaining Shortcut
      After processing first conflict section, if user resolves it, offer: `❓ Apply same action to remaining non-conflict sections? [y/n]`. Only available for non-conflict tail. True conflicts always prompt per-section.

      ### Section h — Plugin-Removed Sections
      If plugin v{Y} no longer has section X but snapshot does:
      - Prompt: `❓ Plugin removed section "## X". Your snapshot has content for it. [keep / drop]`.

      ### Section i — Plugin-Added Sections
      If plugin v{Y} has section X but snapshot/ancestor don't:
      - Auto-add to merged output (no prompt — additive).

      ### Section j — Pre-sync Backup
      Before writing merged snapshot, copy current `.claude/stack-skills/<name>/SKILL.md` to `.claude/stack-skills/<name>/SKILL.md.pre-sync-backup` (single backup, overwritten on next sync per spec §5.5).

      ### Section k — Post-sync Updates
      After merge applied:
      1. Write merged content to snapshot path.
      2. Update registry: `last_synced` = today, `synced_from_plugin_version` = current plugin version, `source` stays `customized`.
      3. Prompt `❓ Re-sync AGENT.md too? [y/n]`. If `y`, repeat sections d-j for `.claude/agents/implementer-<name>.md` vs `{PLUGIN_PATH}/agents/implementer-<name>.md`.
      4. Regenerate CLAUDE.md `<!-- stack-table -->` block (registry changed).
      5. Prompt `❓ Auto-commit "chore: sync <name> stack skill from plugin v{Y}"? [y/n]`.

      ### Section l — `--all` Loop
      For `/sync-stack-skill --all`:
      - Iterate every registry entry with `source != "project"`.
      - For each, run sections c-k. Continue on per-stack abort with summary at end.
      - Single commit prompt at end (batch all syncs).

      ### Section m — Plugin Stack Removal Detection
      During `--all` loop, if a registered stack has `source: customized` but `{PLUGIN_PATH}/skills/implementer-<name>/SKILL.md` doesn't exist (plugin removed it):
      - Warn: `⚠ Plugin no longer ships '<name>' (removed in v{Y}). Your snapshot still works. Convert source to 'project' to keep? [y/n]`.

      ### Section n — Validation
      Same registry validation rules as add-tech-stack section i (spec §5.6).

      AVOID:
      - Don't apply changes silently — every conflict (Both updated) requires per-section user decision.
      - Don't blindly trust apply-all on conflict sections — only non-conflicts.
      - Don't write merged content if user cancels manual-merge — restore pre-sync backup.
      - Don't run sync on `source: project` stacks — they have no plugin source.

      Corresponds to REQ-ID: STACK-04 (3-way merge).
    </action>
