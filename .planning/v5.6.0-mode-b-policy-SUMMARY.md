## Key Decisions

| # | Decision | Rationale |
|---|---|---|
| 1 | Strategy α (runtime enforcement) over β (per-marketplace bundles) | 10x cheaper effort; single source of truth; eliminates drift class of bugs (v5.4.0 marketplace.json drift case still in living memory); preserves user override agency |
| 2 | Default `active_harness: auto` (env detect) | Lowest friction — works without user config change |
| 3 | Fallback to `claude-code` when detection ambiguous | Preserves current v5.5.x behavior; safest default; conservative — keep Mode B available rather than silently disable |
| 4 | Allow user override Mode B on non-Claude with hard warning | Consistent with project's user-decision-wins principle |
| 5 | No Mode B internals refactor | Out of scope; would require multi-month effort for marginal benefit; deferred indefinitely (potentially v7.0+) |
| 6 | Lightweight ceremony — no full 11-step | Scope is small (5 doc/config files + 6 manifests, no logic changes), design fully captured in prior conversation, single-commit patch shape |

## What Worked

- **Prior-conversation-as-spec**: design analysis (Strategy α vs β) had already been done collaboratively with user; spec doc just consolidated. Saved ~30 min vs full brainstorm.
- **Single-commit batched implementer**: opus subagent handled all 5 doc/config edits in one dispatch with surgical precision. No coupling between edits.
- **Lightweight ceremony for tiny patch**: skipped formal Plan Checker, full 4-wave execution, two-stage review per task. Patch shape didn't need it.
- **Reused v5.5.1 release pattern**: version bumps + CHANGELOG + RELEASE-NOTES + tag + push followed exact same shape — predictable and fast.

## What Didn't Work / Lessons

- **`active_harness` index placement**: spec said "index 0 in Display Grouping". Existing convention had indices 1-10 with no 0. Implementer correctly added index 0 and updated the "1-10" range mention to "0-10". Minor spec ambiguity surfaced; resolved by implementer judgment. **Lesson**: when adding to existing conventions, planners should explicitly note convention-shape changes (e.g., "this requires extending the numeric range").

- **No regression test for env detection**: v5.6.0 ships with logical detection rules but no automated probe-and-verify on actual harnesses. Quality risk if env var assumptions are wrong (e.g., maybe Cursor doesn't set `CURSOR_*` consistently). **Mitigation in place**: fallback `claude-code` is conservative — if detection fails silently, behavior is identical to v5.5.x. **Future improvement**: add detection telemetry / `/version` extension to display detected harness for verification.

## Residual Risks

| # | Risk | Mitigation |
|---|---|---|
| R1 | Env var detection unreliable on edge cases (CI environments, nested shells, container runtimes) | Fallback `claude-code` preserves current behavior; explicit `active_harness` field gives users escape hatch |
| R2 | User on non-Claude harness misses warning, force-overrides Mode B, hits partial failure | Warning is bold + prefixed with ⚠; future improvement: log override decisions to STATE.md for audit |
| R3 | Cursor / Codex / OpenCode env var conventions change in future | Conservative wildcard match (`CURSOR_*`); maintainable in single Mode Gate file |
| R4 | Future plugin updates that legitimately need Mode B on Cursor (e.g., Cursor adds Claude-API agent dispatch) | Policy can be updated via single doc edit; no code refactor required |
